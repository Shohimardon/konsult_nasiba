# Nasiba Consultant — ИИ-ассистент на личку Насибы

Telegram-бот, который работает **на личном аккаунте Насибы** через **Telegram Business**
(официально, без риска бана). Отвечает педагогам на вопросы про курсы, принимает чеки
об оплате и проверяет их на жульничество. Спорное и оплату показывает Насибе на подтверждение.

## Что умеет
- **Автоответ по курсам** — цена, дата старта, группа/тоифа, реквизиты. Отвечает на языке
  собеседника (узб. латиница/кириллица, русский), от имени Насибы.
- **Гибрид** — простые вопросы бот закрывает сам; деньги/споры/жалобы → черновик Насибе.
- **Анти-фрод по чекам** — читает чек (скрин или PDF), извлекает сумму, карту, транзакцию.
  Ловит **дубли** (тот же файл или номер транзакции уже присылали) и **чужую карту**
  (получатель не из карт Насибы). Подтверждение оплаты — всегда за Насибой (кнопкой).

## Стек
Python + aiogram 3.13 (Telegram Business API) · PostgreSQL + SQLAlchemy async ·
Anthropic Claude (ответы + зрение для чеков) · ElevenLabs/Groq (голосовые, опц.) · деплой Railway.

## Файлы
- `bot.py` — точка входа, роутеры, polling (с business-апдейтами)
- `config.py` — настройки из `.env`
- `models.py` — ORM: Lead, Course, Receipt, PendingReply, Setting
- `db.py` — async engine, создание таблиц
- `ai.py` — Claude: ответ педагогу + чтение чека (зрение) + распознавание голоса
- `fraud.py` — проверка чека: дубли + сверка карты
- `services.py` — лиды, настройки, сбор «знаний» для ИИ
- `keyboards.py`, `states.py`
- `handlers/business.py` — входящие из личики (FAQ + приём чеков)
- `handlers/approval.py` — одобрение/правка ответов Насибой
- `handlers/admin.py` — команды: /courses, /addcourse, /requisites, /stats, /id

## Настройка (один раз)

1. **Создать бота** у @BotFather → получить `BOT_TOKEN`.
2. **Узнать Telegram ID Насибы** — она пишет боту `/id`, или через @userinfobot. Это `NASIBA_CHAT_ID`.
3. Заполнить `.env` по образцу `.env.example` (токен, ID, карты Насибы, ключ Anthropic, БД).
4. **Подключить бота к личке** (на телефоне Насибы, нужен Telegram Premium):
   `Настройки → Telegram для бизнеса → Чат-боты → вписать @username бота`.
   Включить право **«Отвечать на сообщения»**. Бот пришлёт Насибе «подключение активно».
5. Насиба один раз пишет боту `/start` в обычном чате (чтобы бот мог слать ей черновики),
   затем `/requisites <карта и имя>`.
6. **Курс Milliy — быстрая настройка (по одной команде):**
   - `/setupmilliy` — создаёт единственный курс «Milliy sertifikat (начальные классы)»
     с готовым названием и описанием (3 блока: она тили, математика, педагогика).
     Milliy — это ОДИН экзамен, а не три направления, поэтому и курс один.
   - `/setprice milliy 300000` — цена (нужна, чтобы сверять сумму чека).
   - `/setchannel milliy https://t.me/...` — открытый канал (бот даёт его всем для прогрева).
   - `/setstart milliy 2026-11-15` — дата старта (СЕКРЕТ, бот назовёт только после оплаты).

   Если педагогов готовят по **нескольким категориям** (напр. ещё воспитатели или
   учителя-предметники) — это уже разные курсы: добавь их мастером `/addcourse`,
   и бот будет вежливо уточнять, какой курс нужен.
7. **Закрытые группы (одноразовые ссылки)** — для каждого курса:
   добавить бота в закрытую группу **администратором** с правом «Пригласить по ссылке»,
   затем прямо в этой группе отправить `/bindgroup <ключ_курса>` (напр. `/bindgroup milliy`).
   После этого оплативший педагог получает код → присылает его боту → бот выдаёт
   **одноразовую** инвайт-ссылку (member_limit=1): переслать её бесполезно, сработает один раз.
   Если группу не привязывать — бот отдаёт статичную ссылку из `private_access` (слабее).
8. **Архив чеков (визуальная база)** — создать отдельную **приватную** группу, добавить туда
   бота и отправить внутри неё `/bindreceipts`. После этого каждый присланный чек бот кладёт
   в эту группу: само изображение/PDF + карточка с данными педагога (имя, @username, Telegram
   ID, сумма, карта, вердикт, курс, время). Структурированная база и так пишется в таблицу
   `receipts`; группа — удобный визуальный архив и бэкап. ⚠️ Там платёжные данные — держи
   группу приватной, с минимумом людей.

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env   # и заполнить
python bot.py
```

## Деплой на Railway
- Новый проект + PostgreSQL (как у TezKotib). Railway сам даёт `DATABASE_URL`.
- Переменные из `.env` вписать в Variables. Старт-команда: `python bot.py`.
- Один инстанс polling (не запускать два с одним токеном).

## Важно
- Карты Насибы и реквизиты — чувствительные данные. Храним номера только в `.env`
  (в коде сверяем лишь последние 4 цифры), реквизиты для педагогов — в БД через `/requisites`.
- Подтверждение оплаты никогда не делается автоматически — только по кнопке Насибы.
